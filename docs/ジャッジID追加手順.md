# ジャッジID追加手順

公認ジャッジを新たに追加する(`VALID_JUDGE_IDS`にジャッジIDを追加する)ための手順です。設定の背景やログインAPIの詳細は [judge-login-setup.md](./judge-login-setup.md) を参照してください。

## 前提

- 本番環境はRenderにデプロイされている(`https://dm-ruling-bot.onrender.com`)
- ジャッジIDの命名規則に決まりはない(公式のジャッジ番号、任意のコード名など運用しやすい形式でよい)

## 手順

### 1. 新しいジャッジIDを決める

例:

```text
J003
judge-suzuki
```

既存の値と重複しないIDにする。

### 2. Renderダッシュボードで環境変数を編集する

1. [Renderダッシュボード](https://dashboard.render.com/) にログインする
2. `dm-ruling-bot` サービスを開く
3. 左メニューの **Environment** をクリックする
4. 右上の **Edit** をクリックし、編集モードにする
5. `VALID_JUDGE_IDS` の値欄に、既存の値の末尾へカンマ区切りで新しいIDを追加する

   例: `J001,J002` → `J001,J002,J003`

6. **Save, rebuild, and deploy** をクリックする

### 3. 再デプロイの完了を待つ

- 「Events」または「Logs」タブでデプロイ状況を確認する
- ステータスが **Live** になれば反映完了

### 4. 動作確認する

対象のジャッジ本人にモバイルアプリのログイン画面から新しいジャッジID(例: `J003`)でログインしてもらう。ログインに成功すれば、訂正記録機能が使えるようになる。

### 5. (任意)ジャッジIDの管理記録を残す

誰にどのジャッジIDを発行したか、社内のメモ等に記録しておくことを推奨します(このリポジトリには実在するジャッジIDの一覧を含めないこと — `VALID_JUDGE_IDS`の値は秘密情報として扱う)。

## ジャッジIDを削除する場合

**注意**: `VALID_JUDGE_IDS`環境変数からIDを除去するだけでは削除できません。この変数は起動のたびにDB(`judge`テーブル)へ「まだ存在しないIDだけを追加」する差分シードにのみ使われ、既存の行を削除しないためです(`src/config/env.ts`・起動時シード処理を参照)。DBに行が残っている限り、環境変数から外してもそのジャッジIDは引き続きログインに成功します。

正しい手順は次の2段階です。

1. **DBから削除する**: モバイルアプリの管理者機能(ジャッジ管理画面)、または管理者トークンで`DELETE /api/judges/:judgeId`を呼び出し、対象ジャッジを`judge`テーブルから削除する。`getSession`は`judge`テーブルとのJOINでroleを取得する実装のため、この削除だけで新規ログイン拒否・既存ログインセッションの失効(次回のセッション参照時にJOINが失敗しnullになる)の両方が反映される
2. **環境変数からも除外する**: 上記1だけだと、Renderの次回再デプロイ(再起動)時に`VALID_JUDGE_IDS`に残ったIDが再度DBへシードされ復活してしまう。Renderダッシュボードの`VALID_JUDGE_IDS`からも該当IDを削除し、Save, rebuild, and deployする

手順1のみ・手順2のみではどちらも不完全(1のみ→再デプロイで復活、2のみ→DB行が残り新規ログインも既存セッションも有効なまま)なので、必ず両方実施すること。
