# 公認ジャッジ ログイン機能の設定方法

訂正記録機能(Botの誤答をジャッジが訂正し、DBに蓄積する機能)は、公認ジャッジとしてログインしたユーザーのみ実行できます。この文書は、その設定手順をまとめたものです。

## 1. 有効なジャッジIDを決める

`VALID_JUDGE_IDS` に登録したIDだけがログインできます。IDの命名規則に決まりはありません(公式のジャッジ番号、任意のコード名など、運用しやすい形式で構いません)。

例:

```text
J001
J002
judge-tanaka
```

## 2. `.env` に設定する

プロジェクトルートの `.env` ファイルを開き、`VALID_JUDGE_IDS` にカンマ区切りで有効なジャッジIDを設定します。

```env
VALID_JUDGE_IDS=J001,J002,judge-tanaka
```

- 空欄のままだと、誰もログインに成功できず訂正記録機能も使えません。
- スペースは自動的にトリムされるので、`J001, J002` のように書いても問題ありません。

## 3. サーバーを再起動する

`.env` の変更を反映するため、Botサーバーを再起動してください。

```bash
npm run dev
```

(`npm run dev` は `tsx watch` を使っているため、`.env` 自体の変更検知はしません。手動での再起動が必要です。)

### 本番環境(Render)での設定

本番はRenderにデプロイされているため、ローカルの`.env`ではなくRenderダッシュボード側で設定します。

1. Renderダッシュボード → `dm-ruling-bot` → **Environment** タブを開く
2. `VALID_JUDGE_IDS` の値を編集し、実際に運用する公認ジャッジIDをカンマ区切りで入力
3. 「Save, rebuild, and deploy」で保存すると、自動的に再デプロイされ設定が反映される

## 4. モバイルアプリでの使い方

| API | 画面 | 説明 |
|---|---|---|
| `POST /api/login` | ログイン画面(`login_screen.dart`) | ジャッジIDを入力してログインする。`VALID_JUDGE_IDS` に含まれるIDのみ成功します |
| `POST /api/logout` | 設定画面 | ログアウトする |
| `POST /api/corrections` | 訂正画面(`corrections_screen.dart`) | ログイン中のみ実行可能。直前のBot回答に対する訂正を、ログイン中のジャッジIDと紐付けて記録します |
| `GET/POST /api/judges`, `DELETE /api/judges/:judgeId` | ジャッジ管理画面(`judges_screen.dart`、管理者のみ) | 公認ジャッジの一覧表示・追加・削除 |

## 補足: ログイン状態の扱い

- ログイン状態はセッショントークンごとにDB(`judge_session`テーブル)に保存され、明示的にログアウトするまで有効です(自動的な期限切れはありません)。
- 蓄積された訂正データは「非公式な過去の誤答実績」としてLLMに参考提示されるのみで、公式情報の根拠としては扱われません(指示書の「公式情報のみを根拠とする」方針を守るため)。
