# 公認ジャッジ ログイン機能の設定方法

`/訂正` コマンド(Botの誤答をジャッジが訂正し、DBに蓄積する機能)は、公認ジャッジとしてログインしたユーザーのみ実行できます。この文書は、その設定手順をまとめたものです。

## 1. 有効なジャッジIDを決める

`VALID_JUDGE_IDS` に登録したIDだけが `/login` でログインできます。IDの命名規則に決まりはありません(公式のジャッジ番号、任意のコード名など、運用しやすい形式で構いません)。

例:

```text
J001
J002
judge-tanaka
```

## 2. `.env` に設定する

プロジェクトルートの `.env` ファイルを開き、`VALID_JUDGE_IDS` にカンマ区切りで有効なジャッジIDを設定します。

```env
VALID_JUDGE_IDS=J001,J002,judge-tanaka
```

- 空欄のままだと、誰も `/login` に成功できず `/訂正` コマンドも使えません。
- スペースは自動的にトリムされるので、`J001, J002` のように書いても問題ありません。

## 3. サーバーを再起動する

`.env` の変更を反映するため、Botサーバーを再起動してください。

```bash
npm run dev
```

(`npm run dev` は `tsx watch` を使っているため、`.env` 自体の変更検知はしません。手動での再起動が必要です。)

### 本番環境(Render)での設定

本番はRenderにデプロイされているため、ローカルの`.env`ではなくRenderダッシュボード側で設定します。

1. Renderダッシュボード → `dm-ruling-bot` → **Environment** タブを開く
2. `VALID_JUDGE_IDS` の値を編集し、実際に運用する公認ジャッジIDをカンマ区切りで入力
3. 「Save, rebuild, and deploy」で保存すると、自動的に再デプロイされ設定が反映される

## 4. LINE上での使い方

| コマンド | 説明 |
|---|---|
| `/login <ジャッジID>` | ログインする。例: `/login J001`。`VALID_JUDGE_IDS` に含まれるIDのみ成功します |
| `/logout` | ログアウトする |
| `/訂正 <正しい裁定>` | ログイン中のみ実行可能。直前のBot回答に対する訂正を、ログイン中のジャッジIDと紐付けて記録します。例: `/訂正 1体目は出せますが2体目は出せません` |
| `/whoami` | 自分のLINEユーザーIDを確認する(デバッグ用) |

### 使用例

```text
ユーザー: /login J001
Bot: ジャッジID「J001」でログインしました。/訂正 コマンドが利用できます。

ユーザー: 《カードA》で〜した場合、〜できますか？
Bot: 【結論】 ...(裁定を回答)

ユーザー: /訂正 実際には〜という処理になります
Bot: 訂正を記録しました。今後の類似する質問で参考情報として活用します。

ユーザー: /logout
Bot: ログアウトしました。
```

## 補足: ログイン状態の扱い

- ログイン状態はLINEユーザーIDごとにDB(`judge_session`テーブル)に保存され、明示的に `/logout` するまで有効です(自動的な期限切れはありません)。
- 蓄積された訂正データは「非公式な過去の誤答実績」としてLLMに参考提示されるのみで、公式情報の根拠としては扱われません(指示書の「公式情報のみを根拠とする」方針を守るため)。
