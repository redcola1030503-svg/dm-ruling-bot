## Goal

## Scope

1. **T009 — 同名カードのサジェスト重複排除**
   - 本番`GET /api/cards/suggest?q=輝きは`を1回実行する。
   - 応答が200で、表示名`～輝きは奇跡そのもの～`が1件だけであることを確認する。
   - 公開GET APIのみを使用し、DBは変更しない。
2. **T010 — 回答不能時の無料枠返金**
   - この検証専用のランダムな`deviceId`を生成し、送信前の`GET /api/ruling/usage`が無料枠10件であることを確認する。
   - POST前に、本番`GET /api/cards/suggest?q=ベートーベン`で複数の候補名が返ることを確認する。複数候補にならない場合はPOSTせず停止する。
   - 曖昧カード名「ベートーベン」を含む短い検証用質問を、本番`POST /api/ruling/jobs`へ**1件だけ**送る。`tests/produceRuling.test.ts`の「ambiguousCardsがある場合はLLMを呼ばずneeds_clarificationを返す」が同じ入力を使用している。なおカード名等を解析する最初のLLM呼び出しは必要であり、候補確定後の裁定生成LLMだけが省略される。
   - 作成したjobIdだけを短い間隔でポーリングし、`done`かつ`outcomeStatus=needs_clarification`を確認する。
   - ポーリングは10秒間隔・最大30回（5分）とし、完了しなければ追加送信せず停止する。
   - 完了後の利用状況が10件へ戻っていることを確認する。送信直後の9件は処理完了が速く観測できない可能性があるため必須条件にはしない。
   - `evidence_error`・`llm_error`・`failed`も返金対象なので枠が10件へ戻れば返金機能の確認結果としては有効だが、曖昧名フローの期待とは別結果として記録する。正常回答`ok`やその他の想定外結果になった場合も追加送信せず停止する。
   - 合成deviceId・合成ジョブ1件は本番DBに残り、将来の利用件数分析へ1件混入する。削除や補正は行わず、T020の記録で合成データであることを追跡可能にする（個別IDは記録しない）。
3. **T012 — 既存孤立ジョブの回収**
   - 2026-09-01作成として既に記録されている孤立ジョブについて、本番DBをread-onlyで確認する。
   - 実際のjobId、deviceId、質問文、回答本文は表示・保存せず、対象件数、status、outcome_status、finished_at/refunded_atの有無など必要最小限の集計値だけを取得する。
   - 回収後の期待値は`failed`であり、旧ジョブは`usage_month_key`を持たないため自動返金されない可能性を既存設計どおり区別する。手動更新・返金は本タスクでは行わない。
   - ブラウザのRender Web Shellへ以下のread-onlyコマンドを入力する必要がある場合は、外部UIへのコード入力として実行直前にユーザー確認を取る。`question`、`result_json`、`device_id`、`id`はSELECTしない。行の更新や疑似孤立ジョブの作成は行わない。

```sh
node -e 'const { DatabaseSync }=require("node:sqlite"); const db=new DatabaseSync("/app/data/cache.db",{readOnly:true}); console.log(db.prepare("SELECT status, outcome_status IS NULL AS outcome_is_null, finished_at IS NOT NULL AS has_finished_at, refunded_at IS NOT NULL AS was_refunded, usage_month_key IS NOT NULL AS has_usage_month_key, worker_id IS NOT NULL AS has_worker_id, heartbeat_at IS NOT NULL AS has_heartbeat, COUNT(*) AS row_count FROM ruling_job WHERE created_at >= ? AND created_at < ? AND status = ? AND finished_at - created_at > ? GROUP BY status, outcome_is_null, has_finished_at, was_refunded, has_usage_month_key, has_worker_id, has_heartbeat").all(1788188400000,1788274800000,"failed",86400000))'
```

   - 期間は2026-09-01 JSTの1日、かつ作成から確定まで24時間超の`failed`だけに絞る。既存記録上の孤立ジョブXは57時間超`running`だったためこの条件に含まれ、同日の通常ジョブを大量に返さない。結果が0件または複数の集計行・複数件なら、条件を広げたり個別行をSELECTせず、その時点で確認不能として停止する。
4. **T013 — 購読中の広告非表示**
   - 現行ストア版へT013のコミットが配信済みかを確認する。
   - 未配信なら、本番ストア版では新挙動を確認できないため「未確認」ではなく「未配信のため確認不能」と判定し、次回ストアリリース後に購読中の実機で確認する残タスクとして維持する。
